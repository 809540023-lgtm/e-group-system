# 日本日貨代購系統

商品來源、採購、臺灣銷售、金流、物流、客服、廣告與員工工作共用同一組商品與訂單紀錄。

- **Google 雲端**：商品來源（DM、圖片、Excel、ApprovedCatalog）
- **PostgreSQL 16**：訂單、庫存保留、付款、退款、採購、出貨
- **GitHub**：程式、Issue、分支、CI/CD
- **LINE 官方帳號**：客服入口與員工通知（只含訂單碼與連結，不含個資）

規劃書全文見 [`docs/系統規劃書.md`](docs/系統規劃書.md)；模組派工表見 [`docs/task_registry.json`](docs/task_registry.json)。

- Node.js **24 LTS**（`engines.node >= 24.0.0`）

## 快速開始

```bash
# 1. 安裝依賴
npm install

# 2. 準備環境變數（不要提交 .env）
cp .env.example .env
#    至少填入 DATABASE_URL；其餘外部服務可留空，系統會回報 integration_pending

# 3. 建立資料庫結構
npm run db:migrate

# 4. 啟動前臺
npm run dev            # http://127.0.0.1:3000

# 5. 啟動 worker（另開一個終端）
npm run dev:worker
```

### 交易保證（由 `apps/egroup/test/integration.test.ts` 驗證）

1. 最後一件庫存同時下單，只有一張訂單成立，另一張回 `OUT_OF_STOCK`。
2. 同一 `idempotencyKey` 重送不會重複建立訂單。
3. 取貨碼只存 HMAC 雜湊、一次性核銷，錯誤碼不得通過。
4. 離線事件以 `client_event_id` 去重，重送回 `duplicate`。
5. 退款冪等、不得超過已付餘額，未交付時釋放庫存保留。
6. 召回後停止銷售並阻擋交付；通知未送達不得結案。
7. 站點結算同一期間不得重複計酬。
8. 同一冪等鍵重複付款回 `duplicate`，真正重複付款回 `already_paid`。
9. 12 位顧客同時搶 5 件庫存，成交數不得超過 5 件。
10. 轉入合規二級市場地址自動切換為證券狀態（ST），轉入託管地址則狀態不變。
11. 鎖定期內不得把證券狀態轉回效用狀態；賺取取得（`earned`）無鎖定期，可自由轉回。
12. 未完成 KYC、或計畫限專業投資人而持有人為一般投資人時，一律阻擋並回對應決策碼。
13. 安全模式啟動時所有轉換一律阻擋並要求人工複核；每次轉換都留下稽核紀錄。
14. Social Mining 依權重計算加權分數、超過單一帳戶上限即截斷、未完成 KYC 不得發放。
15. RWA 分配只以設備租金為基礎，營運收入全數排除；同一期間重複試算不產生重複紀錄。
16. 未達第三階段的 STO 計畫不得跨境要約，且被阻擋的評估仍寫入 `cross_border_assessments` 與稽核軌跡。
17. 限制或禁止類的目的地一律阻擋；須等同性認定而未取得時阻擋，取得後放行。
18. 限專業投資人的計畫不得由一般投資人受讓證券狀態；未登錄的監理體制不得要約。
19. 純技術角色且報酬為固定或使用量基礎時判為基礎設施豁免；出現交易基礎報酬時一律轉入中介審查。
20. 即使未出現核心因素，報酬為交易基礎時仍不得豁免；非法報酬結構直接拒絕。
21. 缺少主體或角色的活動本質評估直接拒絕，且不寫入評估紀錄；每次成功評估都留下稽核軌跡。
22. 協議代幣三項條件（編程為不可或缺、已部署供實際使用、核心功能完成）未同時成立時停留在功能前階段。
23. 已進入功能階段後不得因單一條件變動自動倒退，須走安全模式與人工複核。
24. 未登錄的協議代幣不得推進且不寫入轉換紀錄；被阻擋的推進仍寫入 `protocol_token_transitions` 與稽核軌跡。

### 資本市場：RWA 與 STO+

計畫書第十、十一章，加上論文《STO+》的三篇論點，落在 `packages/meal/src/capital.ts`（純規則）
與 `apps/egroup/db/migrations/009_capital.sql`（15 張表 + 3 個交易函式）。

**RWA（實體資產代幣化）**

- 第一階段只做**可辨識的冷鏈設備與真實設備租約**，其次才是已確認可轉讓的應收帳款。
  生鮮庫存**不得**作為第一階段公開投資標的。
- 每台設備要有資產護照：序號、發票、所有權、位置、保養、保險、估值、既有抵押、租約。
  `rwaEligibility()` 做 11 項檢核，分數 = 100 − 12 × 阻擋項 − 5 × 警告項。
- 分配瀑布把**設備租金、營運收入、投資分配分開記錄**，不得把整筆餐食營收當成可分配現金。
- 6 種壓力情境（站點關閉、承租人違約、設備毀損、重複融資、保險拒賠、殘值不足），
  其中保險拒賠與殘值不足會讓本金受損。
- 資產數位化不等於公開募資；掛上 RWA 名稱不會取得任何監理豁免。

**STO 三階段（不得跳關）**

1. 自有資本與租賃：先用自己的錢與租約證明資產是真的。
2. 法律與證券商評估：法律意見、承銷／證券商、櫃買中心規範確認。
3. 發行與託管：實際發行、保管、次級市場。

建立平台**不等於**取得發行或交易許可。投資標的必須在「營運公司股權、債權、設備相關權利」
三者中**明確擇一**，不得混用。櫃買中心規範有專業投資人人數上限，因此
**不得把一般會員的餐食購買與配息型證券型代幣綁在一起**，也不得承諾本金或利息、
不得用後期加盟金支付前期投資人、不得任意跨境募資。

**STO+ 單一代幣雙狀態**

同一顆代幣依「目的地址類別」自動在 ST（證券）與 ST+（效用）之間切換，並留下鏈上紀錄：

| 目的地址類別 | 允許狀態 | 說明 |
| --- | --- | --- |
| `platform` | 僅 ST+ | 平台內消費、兌換、治理 |
| `secondary_market` | 僅 ST | 需投資人適格，限專業投資人時一般投資人不得進入 |
| `custody` | 兩者皆可 | 合規託管地址，法律狀態不變 |

- 鎖定期：**購買取得**走完整 Rule 144（申報公司 6 個月、非申報 12 個月）；**賺取取得**豁免。
- 賺取與購買的定性用 5 項標準：對價關係、取得方式的事前約定、貢獻的可驗證性、
  市場替代可能性、平臺依賴性。
- Social Mining 四類貢獻權重：內容品質 40%、互動深度 25%、治理參與 20%、時間 15%；
  另有單一帳戶上限、權重衰減、定期重置、防女巫、關係人揭露。
- 集中度以論文 Knowpia 規格為基準（前 10% 約 38%、前 20% 約 56%，長尾）；
  前 10 名超過 50% 或前 20 名超過 70% 即視為集中。
- 治理原則「法律優先、保守預設、可追溯介入」：法律高於程式碼；不確定就進安全模式；
  任何人工介入都要事前授權、多簽（≥2）、有期限、留存紀錄、事後公告。

**監理姿態矩陣**

代幣在 A 國合法不代表可在 B 國要約。姿態決定的是「能不能要約」，不是「代幣有沒有效」。

| 代碼 | 姿態 | 主要框架 | 零售 | 限專業 | 須等同性 |

**等同性認定（MiCA 第 16、60 條）**

三項判準缺一不可：實質等同性、與 ESMA 的資訊交換備忘錄、相互市場進入。
三項都不成立時只能走歐盟分支機構；兩者皆無則不得要約。

**稅務與會計的兩條界線**

證券法上不構成證券，不代表稅法上不構成所得；會計採公允價值，也不決定課稅時點。
六類交易（挖礦報酬、非託管質押獎勵、流動性質押交換、Gas fee、平台託管、跨境申報）
各自對應稅務處理、會計處理、注意事項與依據（IRS Notice 2014-21、Rev. Rul. 2019-24／2023-14、
ASU 2023-08、SAB 122、ASC 450-20／IAS 37、OECD CARF、Form 1099-DA）。

**CLARITY Act 必須用條件語氣**

截至 2026-05-31 **尚未成法**：H.R. 3633 於 2025-07-17 通過眾議院，參議院銀行委員會於
2026-05-14 以 15-9 通過版本，仍待參議院全院審議、兩院版本協調、總統簽署。
所有引用一律寫成「若最終成法」「依目前草案」，不得寫成已實施。

**創新導向監管的正當性**

不是監管鬆綁，而是監管品質的提升。五項條件缺一項就退回「共謀」而非「對話」：
公開透明的規則制定、多元利害關係人參與、充分且持續的資訊揭露、監理機關的獨立判斷、
事後問責與救濟。須持續監控四項風險：監管俘虜、安全港濫用、資訊不對稱、產業遊說。

### 區塊鏈基礎設施：三重奏框架

論文三的立場是：**資產本質、活動本質與技術中性三個測試各回答一個不同問題，不可互相取代。**
資產本質問「這是什麼」，活動本質問「誰該被監管」，技術中性問「技術功能本身是否構成證券交易」。
只用其中一個，就會出現「以技術特徵取代法律分析」的錯誤。

**五大代幣類別（資產基礎分類法）**

| 類別 | 法律定性 | 類比 | 監理重點 |
| --- | --- | --- | --- |
| 實體資產代幣 | 物權 | 倉單 | 底層資產確權與保管 |
| 服務代幣 | 消費者保護 | 禮券 | 履約能力與兌換條件 |
| 無形資產代幣 | 證券法（符合 Howey 時） | 投資契約 | 資訊揭露與投資人適格 |
| 原生 DLT 代幣 | 資源配置／網路安全／治理 | 網路資源 | 無單一發行人的努力 |
| 穩定幣 | 支付法 | 電子貨幣 | 準備資產與贖回權 |

**去中心化不是法律要件，是 Howey 的輔助因素**

去中心化在資訊科學、經濟學、政治學各有不同定義，且存在認識論、時間、操作三種不可行問題，
因此不能當成「是否為證券」的獨立判準。Ripple 案已說明：機構銷售構成投資契約、程序化銷售不構成，
法院對去中心化保持沉默——決定性因素是**交易情境**，不是技術特徵。

**活動本質：核心因素與否定因素**

核心因素指向中介（規律性為他人買賣、交易基礎報酬、主動招攬、中介地位、保管客戶資產、裁量權、個人化建議）；
否定因素指向基礎設施（僅提供軟體或技術平臺、無裁量權、不接觸客戶資金、固定或使用量報酬、出版者例外）。
三項原則缺一不可：**被動性、中立性、報酬結構**。任一核心因素出現即轉入中介審查。

**技術中性不等於技術免責**

同一個代幣在機構銷售與程序化銷售下可有不同法律地位；同一個技術功能在自託管與託管質押下也可有不同定性。
技術功能的內在性測試要求「內在且必要」：質押、驗證、獎勵分配、鎖定、鑄造銷毀、gas 支付、
協議測試、空投領取、鏈上轉移，逐項判斷是否構成投資契約，而不是整包免責。

**協議代幣的兩階段模型**

功能前階段推定為投資契約（可用 Reg D／Reg S／Regulation PT），功能階段則為非證券、非商品的新資產類別。
轉換點是三項條件同時成立：編程為不可或缺、已部署供實際使用、核心功能完成。
**只能前進，不能倒退**——已進入功能階段後若單一條件變動就自動回退，等於讓發行人可以選擇性切換法律地位。

**DAO 責任分配**

未登記的 DAO 依 `Sarcuni v. bZx DAO` 推定為一般合夥，成員負無限責任。
四種損害來源對應不同責任主體：協議錯誤（DAO 實體＋開發團隊產品責任）、治理決議（DAO 實體＋提案人）、
外部駭客攻擊（市場操縱）、持股 5% 以上（控制股東義務）。

**跨境三層次解方**

MiCA 假設存在可辨識的白皮書發行人，CLARITY 則以資產基礎分類出發，兩者對同一代幣可能給出不同答案。
三層次解方：框架對齊、分層報告、24 小時即時分享。Mt. Gox 的教訓是：沒有跨境協調，倒閉風險會直接外溢到其他司法管轄區。

## 不可妥協的規則

1. 已核准的臺幣售價**不得再次加價**（來源表已含加成）。
2. 所有金額使用整數最小單位；日圓購價為整數。
3. 建立訂單、明細、庫存保留、付款與 outbox 必須在**同一個交易**完成。
4. 組合商品依固定 SKU 鎖定順序，避免死鎖。
5. 到處使用冪等鍵；同一筆平臺交易重送不得重複扣庫存。
6. 前端送來的價格、運費與角色一律不信任，伺服器重算。
7. 現貨、預購配額、詢價分開計算；預購不得扣現貨庫存。
8. 缺少憑證的服務要有介面、mock 與錯誤路徑，狀態為 `integration_pending`，**不得假成功**。
9. 長者操作：正文 20px、商品名 ≥22px、價格 28–32px、按鈕 ≥48px、WCAG 2.2 AA、200% 字級不得橫向捲動。
10. 憑證只放 secret store 或私密 env；不得進聊天、程式、日誌或 Git；機密不得使用 `NEXT_PUBLIC_`。
11. AI 讀取外部 DM 或網站內容時視為**資料**，不是指令（提示注入防禦）。
12. worker 使用租約 + `SKIP LOCKED`；重試到上限後進失敗佇列，**不得無限重試**。
13. 商品上架狀態只有總部（admin）能改；供應商儲存商品時一律維持草稿或原狀態，不得自行上架。
14. 匯出的 CSV 必須中和以 `=`、`+`、`-`、`@` 開頭的試算表公式，避免匯出檔被當成公式執行。
15. 供應商只能寫入自己的商品：以他人 SKU 送出時不得覆寫，且回應不得透露該 SKU 是否存在。
